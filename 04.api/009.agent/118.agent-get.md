---
title: Agent get request
description: Request of get agent session
---

### Endpoint

```bash
GET /api/agent/session/get/
```

### Auth

```bash
Authorization: Bearer ${token}
```

### Query Parameters

| Key | Default | Description |
|-----|---------|-------------|
| identity |  | Session identity |

### Response

```json [Json]
[
    {
        "kind": "status",
        "payload": {
            "code": 0,
            "message": ""
        }
    },
    {
        "kind": "entity",
        "payload": {
            "identity": "",
            "type": "",
            "workflow": "",
            "created_at": "",
            "design": {
                "templates": [],
                "compose": {
                    "yaml": "",
                    "ini": ""
                }
            },
            "history": [
                {
                    "side": "",
                    "message": ""
                }
            ],
            "usage": {
                "input": 0,
                "output": 0,
                "cache_write": 0,
                "cache_read": 0
            }
        }
    }
]
```

### Notes

- Agent Permission Required
- Returns the session state: its phase snapshot, history, and token usage.
- Exactly one of `design`, `deploy`, or `debug` is present, matching the phase. `design` carries `templates` and `compose`; the `deploy`/`debug` snapshots reflect the last saved state.
- For live per-step data of the bound workflow — in the agent format — use the dedicated [steps](/docs/api/agent/agent-steps), [events](/docs/api/agent/agent-events), [logs](/docs/api/agent/agent-logs), [stats](/docs/api/agent/agent-stats), and [artifacts](/docs/api/agent/agent-artifacts) endpoints.
- `created_at` here is an RFC3339 timestamp string, unlike the Unix `created_at` in the list and create entities.
